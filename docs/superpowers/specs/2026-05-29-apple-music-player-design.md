# Apple Music 风格音乐播放器设计文档

## 1. 目标

在 `macOS + SDL` 环境下，为当前工程设计并实现一个 `LVGL v9` 风格音乐播放器界面，屏幕基准尺寸为 `800x480`，整体视觉参考 `Apple Music`，信息架构以“广播优先”作为首页主心智。

本次需求分为两个阶段：

1. 先实现 `HTML` 高保真视觉样机，用于快速确认布局、层级、配色与整体气质。
2. 在视觉确认后，再实现 `LVGL v9` 版本 UI。

`LVGL` 阶段必须将 `flex/grid` 作为主要布局手段，而不是依赖大量绝对坐标。目标是让后续分辨率调整、自适应和模块增减时，界面结构仍可稳定演进。

## 2. 本次范围

本次只做 `UI` 与界面交互外观，不接真实播放能力。

明确包含：

- `macOS SDL` 下可运行的界面
- 默认进入 `主页`
- 左栏一级导航
- `主页 / 广播 / 本地 / 歌单 / 设置` 五个页面入口
- 底部常驻迷你播放条
- `设置` 页中的主题颜色切换
- 主题切换后的全局视觉联动
- 一套 `HTML` 样机版本
- 一套 `LVGL v9` 版本

明确不包含：

- 真实音频播放
- 本地文件扫描
- 广播流接入
- 搜索功能
- 播放列表管理逻辑
- 系统级媒体控制

## 3. 信息架构

左栏固定五个一级项：

- `主页`
- `广播`
- `本地`
- `歌单`
- `设置`

页面职责如下：

### 3.1 主页

默认页。承担“进入应用后第一眼内容组织”的职责，优先突出广播推荐，其次提供最近播放回流与全局播放状态展示。

### 3.2 广播

独立广播浏览页。比主页更聚焦电台、频道、精选节目与立即收听入口。

### 3.3 本地

本地资料库页。当前阶段用静态假数据承载歌曲或专辑列表，先验证页面结构。

### 3.4 歌单

歌单页。展示用户歌单与推荐歌单卡片，先做静态内容和视觉层级。

### 3.5 设置

独立整页设置，不使用弹窗或抽屉。当前阶段重点承载：

- `主题模式`
- `主题颜色`
- 若干外观占位项

## 4. 首页设计

首页采用广播优先的 `Apple Music` 风格推荐布局，适配 `800x480` 横屏。

### 4.1 左栏

左栏宽度控制在约 `150-165px`。

结构从上到下：

- 一级导航项：`主页 / 广播 / 本地 / 歌单`
- 底部独立项：`设置`

视觉规则：

- 使用浅色半透明面板
- 当前选中项用 `Apple Music` 风格高亮色强调
- 不使用重边框或复杂图标装饰
- 优先用留白、圆角和色块区分层级

### 4.2 右侧内容区

右侧内容区分成三层：

1. `顶部信息区`
2. `主推荐卡`
3. `双列内容区`

#### 顶部信息区

左侧显示：

- `主页` 标题
- 一句情绪化文案，例如“早上好，现在适合从广播开始”

右侧保留搜索框占位，仅用于视觉结构，不实现搜索逻辑。

#### 主推荐卡

主页最显眼区域，承担品牌气质与首页节奏。

内容包括：

- 广播主题标题
- 一句副标题或节目说明
- `继续收听`
- `探索更多`
- 右侧抽象封面或节目视觉块

视觉重点：

- 大圆角
- 柔和渐变
- 玻璃感面板
- 轻阴影
- 强留白

#### 双列内容区

左列为 `推荐广播`，右列为 `最近播放`。

`推荐广播`：

- 3 条电台条目
- 每条包括封面、名称、说明与播放按钮

`最近播放`：

- 3 条内容
- 可混合单曲、歌单、广播
- 用于承接“继续使用”的路径

### 4.3 底部迷你播放条

全局固定常驻，不随右侧页面切换消失。

结构：

- 左：当前内容封面、标题、作者
- 中：上一首、播放、下一首
- 右：进度条与时间

当前阶段只做外观与基础状态切换，不接真实播放。

## 5. 设置页设计

设置页为独立整页。

### 5.1 页面结构

设置页右侧内容区再拆成：

- 左侧分组导航
- 右侧设置内容

分组导航包括：

- `外观`
- `播放`
- `关于`

当前阶段重点完成 `外观` 分组，其余两组做占位 UI。

### 5.2 外观设置内容

外观页包含以下模块：

#### 主题模式

- `浅色`
- `深色`
- `跟随系统（占位）`

本阶段至少保证浅色主题完成，深色主题做结构预留。

#### 主题颜色

做成四个单选色板：

- `Pink`
- `Blue`
- `Mint`
- `Orange`

切换主题颜色时，仅改动核心视觉 token，不改变信息架构。

联动范围包括：

- 左栏选中态
- 首页主推荐卡渐变主色
- 按钮强调色
- 播放进度条高亮色
- 交互选中态

#### 外观细节

可放两个占位项：

- `圆角强度`
- `背景氛围`

本阶段只要求 UI 可见，不要求真实联动。

## 6. 交互规则

### 6.1 页面切换

不采用“整屏销毁重建”的粗粒度方式作为主要设计思路。

推荐结构：

- 根容器承载整屏
- 左栏固定
- 右侧内容区按导航项切换
- 底部迷你播放条固定

也就是说，`主页 / 广播 / 本地 / 歌单 / 设置` 切换时，优先只替换右侧主内容。

这样更利于后续继续接真实逻辑。

### 6.2 主题切换

需要维护一组统一主题状态：

- `当前主题模式`
- `当前主题颜色`

切换时允许：

- 刷新共享样式
- 重建右侧内容区
- 重建播放条样式

在纯 UI 阶段，这是合理且可接受的。

### 6.3 假数据策略

由于当前不接真实功能，各页面使用静态假数据：

- `广播`：节目、电台列表
- `本地`：歌曲或专辑列表
- `歌单`：推荐歌单卡片
- `播放条`：当前播放内容占位

目标是保证各页面视觉完整，不出现空白内容页。

## 7. HTML 样机阶段要求

`HTML` 阶段的职责不是实现业务功能，而是快速确认：

- 页面信息架构
- 视觉层级
- 颜色系统
- 间距节奏
- 主题切换效果
- `Apple Music` 风格是否成立

要求：

- 在桌面浏览器中展示基准 `800x480` 视口 mockup
- 首页、设置页必须完成
- 左栏导航与主题颜色切换需要有基础交互表现
- 广播、本地、歌单页可先做静态内容版

HTML 样机通过后，才进入 LVGL 实现。

## 8. LVGL 实现阶段要求

### 8.1 运行环境

- `macOS`
- `SDL`
- 不使用 `FreeRTOS`

应用入口应基于当前 SDL 路径组织，默认进入音乐播放器 UI。

### 8.2 布局约束

`LVGL v9` 版本必须优先使用：

- `flex`
- `grid`

来组织页面结构。

明确要求：

- 左栏与主内容区使用容器布局而非硬编码绝对坐标
- 首页主推荐区与双列区使用 `flex/grid` 进行分区
- 设置页两列结构使用 `grid` 或等价布局容器组织
- 播放条内部使用 `flex` 对齐标题、控制按钮与进度

只允许在少数视觉装饰元素上使用必要的绝对定位，例如：

- 主推荐卡抽象装饰块
- 某些浮层高光元素

禁止整个页面依赖绝对定位拼装。

### 8.3 自适应目标

虽然本次基准尺寸是 `800x480`，但布局设计必须为后续分辨率调整留接口。

因此：

- 宽高比例变化时，模块优先按容器重新排布
- 文本区、列表区、卡片区应具备弹性伸缩能力
- 不将所有尺寸写死在单一像素值上
- 对间距、圆角、块宽等视觉尺寸，尽量形成一组集中 token 或风格参数

## 9. 组件拆分建议

实现时建议拆成以下 UI 单元：

- `导航栏`
- `主页内容`
- `广播页`
- `本地页`
- `歌单页`
- `设置页`
- `迷你播放条`
- `主题状态/样式层`

其中：

- 导航栏与迷你播放条为全局常驻模块
- 各页面仅负责右侧内容区
- 主题状态用于集中管理颜色和模式切换

## 10. 验收标准

以下条件同时满足，视为本次 UI 设计与实现目标完成：

### 10.1 HTML 样机验收

- 存在可打开的 `HTML` 样机
- 默认展示 `800x480` 横屏效果
- 首页结构与设计文档一致
- 设置页可展示主题颜色切换
- 用户可据此确认整体风格

### 10.2 LVGL UI 验收

- `macOS SDL` 可运行
- 默认进入 `主页`
- 左栏五项可切换
- 底部迷你播放条常驻
- `设置` 页可切换至少四套主题色
- 切换主题色后，主页、左栏、播放条出现联动变化
- 页面主体布局确实采用 `flex/grid` 组织，而非全量绝对定位

## 11. 后续扩展方向

当 UI 样机阶段完成后，后续真实能力可按如下顺序接入：

1. 本地假数据替换为真实媒体数据源
2. 迷你播放条接真实播放状态
3. 广播页接真实频道或流地址
4. 搜索入口接真实检索
5. 深色模式与更多主题完善

本设计文档只为当前 UI 阶段和后续可扩展结构提供边界，不提前承诺播放内核方案。
