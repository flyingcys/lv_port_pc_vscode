# Apple Music 播放控制区按钮优化设计

## 背景

当前 `main/src/v9_apple_music` 底部播放器控制区的 `上一首 / 播放 / 下一首` 按钮采用 Unicode 字形图标，视觉上偏粗、缺少层级，和参考稿 `design-ui/music/music-player-macos.html` 的 macOS Music 风格存在明显差距。

本次目标是对齐参考稿中的控制区气质，重点优化传输键的图形、尺寸、间距和交互反馈，同时保持现有播放逻辑不变。

## 目标

- 对齐参考稿中的控制区视觉层级与留白节奏。
- 重做 `上一首 / 播放 / 下一首` 三个按钮的图标形态。
- 统一三键命中区、间距和按压反馈，降低默认 LVGL 控件感。
- 保持 `am_player.c` 中的播放、切歌、刷新逻辑可复用，仅调整播放态 UI 切换方式。

## 非目标

- 不修改进度条与音量条的行为。
- 不改动页面结构、列表弹层和播放来源逻辑。
- 不重做 `模式`、`播放列表` 两个外围按钮，仅保持它们与传输键的间距协调。
- 不引入复杂自绘回调、Canvas 或额外渲染依赖。

## 方案比较

### 方案一：保留布局骨架，重做传输键组件

- 只调整底部播放器控制区的按钮构造方式。
- `上一首 / 下一首` 改为几何图元拼装，`播放 / 暂停` 改为显隐切换。
- 风险低，改动集中，能最大化贴近参考稿。

### 方案二：继续使用字形图标，仅微调字号和间距

- 修改成本最低。
- 但 `⏮ / ⏭ / ▶` 的视觉气质与参考稿差距较大，最终效果有限。

### 方案三：引入自定义绘制

- 视觉自由度最高。
- 但需要额外处理绘制与状态同步，超出本次按钮优化的合理复杂度。

### 结论

采用方案一：保留现有播放器结构，仅替换三枚核心传输键的视觉实现。

## 设计说明

### 组件边界

- 保留现有 `pbar -> ctrls -> btn_prev / btn_play / btn_next` 层级。
- `btn_prev`、`btn_play`、`btn_next` 仍为普通 `lv_obj` 点击容器。
- `btn_mode`、`btn_playlist` 继续沿用文字图标按钮。
- 所有播放、上一首、下一首事件回调接口保持不变，继续复用现有事件绑定。

### 视觉规格

- 图标默认色使用 `#2a2a2e`，与参考稿一致。
- 按压态使用极浅灰底与更深图标色，反馈克制，不添加夸张动画。
- `上一首 / 下一首` 命中区保持约 `30x30`。
- `播放 / 暂停` 命中区保持约 `34x34`，作为视觉中心。
- `上一首 / 下一首` 使用“竖条 + 三角”组合，不再使用 Unicode 字形。
- `播放` 使用单个偏右重心的实心三角。
- `暂停` 使用两根细长竖条，视觉重量与播放三角保持接近。
- 控制组整体采用更紧凑、均衡的横向间距，贴近参考稿节奏。

### 状态切换

- 默认态：透明背景，仅显示图形。
- 按压态：按钮容器显示轻微底色反馈。
- 播放态切换：由 `am_player_refresh_ui()` 控制 `播放图形 / 暂停图形` 的显隐，而不是替换文字内容。

## 实现计划

### UI 组装

- 在 `main/src/v9_apple_music/am_shell.c` 中保留现有文字图标按钮构造器，供 `模式` 和 `播放列表` 使用。
- 新增传输键构造器，分别生成：
  - 上一首按钮
  - 播放/暂停按钮
  - 下一首按钮
- 通过普通 `lv_obj` 子对象拼装几何图标，避免引入复杂绘制逻辑。

### 句柄扩展

- 在 `main/src/v9_apple_music/am_player.h` 的 `am_miniplayer_handles_t` 中新增中心按钮内部图形句柄。
- 最少需要暴露：
  - 播放三角对象
  - 暂停左竖条
  - 暂停右竖条

### 刷新逻辑

- 在 `main/src/v9_apple_music/am_player.c` 中保留原有播放状态查询逻辑。
- 将播放按钮的状态刷新从 `label` 文本切换改为图形显隐切换。
- 上一首、下一首逻辑不变，仅沿用新的按钮外观。

## 风险与验证

### 风险

- 如果仍保留原 `play_icon` 单句柄，会限制播放/暂停图形切换的表达能力。
- 如果按钮内部对象的点击标志未清理，可能影响事件命中。
- 如果控制区间距调得过紧，480 高度下会出现视觉拥挤。

### 控制措施

- 扩展 `am_miniplayer_handles_t`，显式保存中心按钮内部图形对象。
- 几何图元全部关闭滚动与点击，保证事件命中在按钮容器上。
- 改动前对目标符号执行 GitNexus impact，确认调用面与流程风险。
- 实现后至少完成一次编译验证，并在提交前执行 GitNexus 变更检测。

## 验收标准

- 底部 `上一首 / 播放 / 下一首` 三个按钮视觉明显接近参考稿。
- 播放按钮在播放/暂停两种状态下正确切换图形。
- 按钮点击行为与改动前一致，不影响切歌和播放控制。
- 项目可正常编译通过。
