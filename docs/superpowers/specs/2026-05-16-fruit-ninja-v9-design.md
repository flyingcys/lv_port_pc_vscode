# LVGL v9 Fruit Ninja 设计规格

## 目标

在当前 PC simulator 工程中实现一个真正可运行的 LVGL v9 版 Fruit Ninja，启动程序后直接进入游戏场景。视觉资源、背景图、首页元素、果实图片、音效与背景音乐都以 `third-party/FruitNinja` 为真值来源；`third-party/lvgl-fruit_ninja` 仅作为 LVGL v8 动画节奏和对象组织参考，不直接移植其 C 数组资源方案。

## 已确认约束

- 交付形态：直接集成到当前 PC simulator，程序启动后直接进入 Fruit Ninja 场景。
- 资源要求：图片和声音都必须走文件，不允许将资源转成 C 数组内嵌。
- 图片格式：至少支持本地 `png` 和 `jpg/jpeg` 文件读取。
- 声音格式：优先直接支持 `ogg` 与 `mp3` 文件读取和播放。
- 输入方式：第一版仅要求鼠标拖拽切割，保证 PC simulator 上真实可玩。
- 效果目标：尽量对齐 `third-party/FruitNinja` 的背景、音乐、果实、分裂、爆炸、首页和结算表现。

## 参考真值与取舍

### `third-party/FruitNinja`

作为玩法和资源真值，重点参考：

- `images/background.jpg`：游戏背景。
- `images/logo.png`、`images/new-game.png`、`images/game-over.png`、`images/score.png`、`images/x*.png`：首页、结算和 HUD 元素。
- `images/fruit/*.png` 与对应 `*-1.png` / `*-2.png`：完整果实与切开后的两半资源。
- `images/shadow.png`、`images/flash.png`、`images/smoke.png`、`images/lose.png`：阴影、刀光、爆炸/失败附加动效。
- `sound/menu.*`、`sound/boom.*`、`sound/over.*`，以及切水果相关声效文件：背景音乐与音效真值。
- `scripts/all.js`：果实配置、出场节奏、刀痕、得分、失败、炸弹爆炸逻辑真值。

### `third-party/lvgl-fruit_ninja`

只作为 LVGL 侧参考：

- 果实对象管理、基础动画拆分、切中后生成两半、血浆/爆炸的对象组织方式。
- 不复用其中的图片 C 数组和旧版 `lv_img_*` / `lv_disp_*` 语义。
- 所有资源路径、输入判定、游戏状态和动画参数在 v9 下重新组织。

## 推荐实现路线

采用“LVGL v9 + 文件资源 + SDL 系音频/图像能力”的方案：

- LVGL v9 负责场景、对象、动画、事件、HUD 和游戏状态机。
- 图片通过 LVGL v9 已有文件解码链从磁盘直接读取，启用 PNG/JPEG 支持。
- 声音通过新增本地依赖完成文件播放，优先选 `SDL2_mixer`，因为当前工程已经基于 SDL2 跑 PC simulator，接入成本和运行稳定性最高。
- 游戏逻辑在 `main/src/v9-fruit_ninja` 下完全独立实现。

不采用的路线：

- 不把大部分循环下沉到纯 SDL 游戏框架，因为会偏离“LVGL v9 版本”的目标。
- 不强行从 v8 代码原样迁移，因为 v8 API、资源模型和当前文件资源目标都不兼容。

## 模块划分

计划在 `main/src/v9-fruit_ninja` 下建立以下模块：

1. `fruit_ninja_entry.*`
   - 对外暴露单一入口。
   - 创建并装载游戏根场景。

2. `fruit_ninja_assets.*`
   - 统一管理资源根目录。
   - 负责拼接图片与音频文件路径。
   - 提供关键资源存在性检查和初始化校验。

3. `fruit_ninja_audio.*`
   - 初始化/销毁音频子系统。
   - 背景音乐循环播放。
   - 命中、爆炸、失败等音效触发。
   - 提供统一静音/停止接口，避免游戏切场景时泄露音频状态。

4. `fruit_ninja_model.*`
   - 定义果实种类、场景状态、得分、剩余失败次数、运行时实体结构。
   - 管理活跃果实列表和分裂碎片列表。

5. `fruit_ninja_view.*`
   - 创建背景、首页按钮/标题、HUD、失败图标、Game Over 图等视图对象。
   - 管理屏幕级对象层级，保证背景、刀痕、果实、前景特效、HUD 分层清晰。

6. `fruit_ninja_spawn.*`
   - 根据节奏定时生成普通水果和炸弹。
   - 负责初速度、起始位置、角速度等随机参数。

7. `fruit_ninja_physics.*`
   - 按帧或按定时器推进果实抛物线、旋转、阴影、分裂后碎片下落。
   - 负责越界回收与漏切判定。

8. `fruit_ninja_input.*`
   - 处理鼠标按下、拖拽、释放。
   - 保存最近一段轨迹点，生成刀痕折线，并给出最新切割线段。

9. `fruit_ninja_collision.*`
   - 对拖拽线段与活跃果实圆形碰撞体进行相交判定。
   - 一次切割应避免同一果实被重复计分。

10. `fruit_ninja_scene.*`
    - 串联首页、开局、运行中、爆炸结束、失败结算、重新开始流程。
    - 负责定时器启停与音频/动画联动。

如果实际实现中发现文件数过多，可将 `spawn/physics/collision` 合并成较少的逻辑文件，但仍保持职责边界不混乱。

## 资源加载设计

### 图片

- 通过 LVGL v9 文件路径直接加载，例如 `lv_image_set_src(obj, "S:path/to/file.png")` 或当前平台启用的标准文件前缀。
- 构建层面启用 PNG/JPEG 解码能力，保证 `background.jpg` 和全部果实 png 资源可直接读取。
- 对首页、HUD、Game Over 等固定图片统一封装成路径常量，避免散落硬编码。

### 声音

- 新增 `SDL2_mixer` 依赖，初始化音频设备。
- 背景音乐：菜单/开局时播放 `menu.ogg` 或 `menu.mp3`，循环播放。
- 音效：至少接入切水果、炸弹爆炸、游戏结束 3 类关键音效；若仓库内存在更多可用切割音效，则一并使用。
- 资源选择优先级：`ogg` 优先，其次 `mp3`，因为 OGG 在 SDL_mixer 上通常依赖更少、兼容性更稳。

### 路径策略

- 资源根目录基于工程根目录下的 `third-party/FruitNinja` 统一推导。
- 业务逻辑层只使用资源键名，不直接拼绝对路径。
- 若资源缺失，初始化阶段输出明确错误日志并进入可诊断失败态，而不是无提示黑屏。

## 画面与场景设计

### 启动即进入首页

程序启动后直接载入 Fruit Ninja 首页，尽量对齐网页版主要视觉元素：

- 背景图 `images/background.jpg`
- `logo.png`
- `new-game.png`
- 必要时保留 `ninja.png`、`home-mask.png`、`home-desc.png` 等氛围图层
- 播放菜单背景音乐

第一版允许对首页动画做适度简化，但必须保持主要元素和风格一致，并能点击/拖拽进入游戏。

### 运行中 HUD

- 左上或与网页版近似位置展示分数图标和当前得分。
- 顶部展示 3 次失误机会，切水果漏掉时逐个点亮失败标记。
- 炸弹命中立即触发结束，不消耗失败次数。

### Game Over

- 游戏结束时显示 `game-over.png`。
- 停止生成新果实，停止或切换背景音乐，播放结束音效。
- 提供重新开局能力，至少支持点击屏幕或按钮重新开始。

## 游戏状态机

定义以下最小状态：

1. `HOME`
   - 展示首页资源。
   - 背景音乐循环播放。
   - 等待开始。

2. `RUNNING`
   - 启动果实生成定时器和物理更新定时器。
   - 接受切割输入。
   - 正常计分、漏切、爆炸判定。

3. `EXPLODING`
   - 命中炸弹后的短暂演出状态。
   - 暂停新果实生成，展示白闪/爆炸特效。

4. `GAME_OVER`
   - 展示 Game Over。
   - 停止所有活跃游戏对象定时器。
   - 等待重新开始。

状态切换必须显式停止或恢复对应定时器和音频，避免进入新局后残留旧局对象。

## 果实模型设计

### 类型

第一版至少支持：

- `apple`
- `banana`
- `peach`
- `sandia`
- `basaha`
- `boom`

对应网页版 `infos` 配置中的图片、尺寸、半径、默认角度偏移、汁液颜色。尺寸和碰撞半径以网页版配置为主，必要时允许做轻微 LVGL 实际显示校正。

### 实体字段

每个活跃实体至少包含：

- 类型
- 是否炸弹
- 当前坐标
- 当前速度向量
- 重力加速度
- 当前旋转角
- 角速度
- 碰撞半径
- 是否已被切开
- 是否已记入漏切
- 主图对象
- 阴影对象
- 分裂后左右半图对象（可空）
- 创建时间/生命周期信息

### 运动

- 从屏幕底部或偏底部区域随机起飞。
- 使用简化抛物线：`vx` 恒定，`vy` 受重力递增。
- 阴影相对果实做固定偏移，增强接近网页版的悬浮感。
- 普通水果带持续旋转；炸弹可做特殊火焰/高亮效果，但第一版可简化为旋转 + 爆炸反馈。

## 切割输入与刀痕设计

### 输入

- 监听鼠标按下、拖拽、释放。
- 按下开始记录一段新的刀轨。
- 拖拽时持续追加点，并生成最新线段。
- 释放后短时间内淡出刀痕。

### 刀痕视觉

- 使用 LVGL 折线、Canvas 或少量线段对象绘制轨迹。
- 轨迹有寿命衰减，最近片段更粗更亮，旧片段快速淡出。
- 第一版不强求像网页版一样完全一致，但要明显具备“刀光”效果。

### 碰撞判定

- 以拖拽生成的最新线段与果实圆形近似碰撞体求交。
- 命中后立即标记该果实为已切开，避免同一帧多次加分。
- 切中炸弹时直接进入爆炸结束流程。

## 切中后的表现

### 普通水果

- 隐藏完整水果图。
- 生成 `*-1.png` 与 `*-2.png` 两半图。
- 两半沿不同水平速度继续下落，并各自旋转。
- 播放切中音效。
- 显示刀光/汁液/闪切特效，优先复用 `flash.png`、`smoke.png` 等现有资源；若某些网页版特效不适合直接照搬，可先实现刀光和基础飞溅。
- 分数加一并刷新 HUD。

### 炸弹

- 播放爆炸音效。
- 显示爆炸或白闪特效。
- 进入 `EXPLODING -> GAME_OVER` 流程。

## 漏切与失败规则

- 普通水果落出屏幕底部且未被切开时，记一次漏切。
- 漏切后播放失败提示动效，并点亮一个失败标记。
- 失败累计到 3 次进入 `GAME_OVER`。
- 炸弹不参与漏切计数。

## 与当前工程的集成点

### 启动入口

- 修改 `main/src/main.c`，将 `lv_demo_widgets()` 替换为 Fruit Ninja 场景入口。
- 保持当前 `lv_init()` 与 SDL display/input 初始化流程不变。

### 构建系统

- 在 `CMakeLists.txt` 中启用 PNG/JPEG 相关选项和依赖。
- 新增 SDL2_mixer 查找与链接。
- 将 `main/src/v9-fruit_ninja/*.c` 或 `*.cpp` 纳入构建。

### LVGL 配置

- 保证 `lv_conf.h` 中对应文件系统与图像解码配置可用。
- 若当前默认未开启某些解码器，需要在构建选项和 `lv_conf.h` 上统一打通。

## 测试与验收标准

### 必须满足

- 项目能成功构建。
- 启动后直接进入 Fruit Ninja 首页或主场景，而不是通用 LVGL demo。
- 背景图、果实图、分裂图都来自文件资源，不是 C 数组。
- 鼠标拖拽可以真实切开水果。
- 分数、失败计数、炸弹 Game Over 都可工作。
- 背景音乐和至少 3 类关键音效可从文件真实播放。
- 重新开始后状态干净，不残留上一局对象与音频。

### 建议验证

- 最小自动化验证：资源初始化、状态机基本流转、关键路径拼接。
- 手工验证：启动、首页、开局、切中普通水果、切中炸弹、漏掉 3 个水果、重开一局。

## 风险与应对

1. 图片文件解码未完全启用
   - 先在构建层明确启用 PNG/JPEG 选项，并用单图加载做最小验证。

2. SDL2_mixer 在本机依赖缺失
   - 在 CMake 配置阶段提前暴露错误，而不是拖到运行期。
   - 若系统缺少某编解码支持，优先使用仓库已有 `ogg` 资源路径。

3. LVGL 直接旋转外部文件图片的性能或表现不理想
   - 第一版可接受适度降低同时在场果实数，先保证玩法正确和运行稳定。

4. 网页版首页动效过于复杂
   - 第一版优先还原主要视觉元素和游戏玩法闭环；复杂首页位移/弹跳动画可做适度简化，但不得缺失关键资源和氛围。

## 非目标

- 第一版不做触摸多指优化。
- 第一版不追求网页版所有粒子特效逐像素一致。
- 第一版不做排行榜、本地存档、设置菜单等扩展能力。
- 第一版不兼容嵌入式资源受限平台，只先保证当前 PC simulator 可运行、可玩、可验证。
