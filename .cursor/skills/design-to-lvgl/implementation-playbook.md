# 实施工作流

本文件只描述通用执行顺序，不重复展开来源特化规则；`MasterGo` 和 `Figma` 的差异分别看对应 reference 文件。

## 推荐工作流

把下面清单复制到 todo 中并持续更新：

```text
- [ ] 锁定设计源与页面范围
- [ ] 读取对应 MCP schema 并提取设计数据
- [ ] 输出页面结构摘要、资源方案、字体方案
- [ ] 输出关键设计值对照表
- [ ] 规划 LVGL 模块与修改文件
- [ ] 落地图标、背景、字体到本地
- [ ] 必要时用 asset_tool.py 生成预合成资源
- [ ] 实现 LVGL 页面
- [ ] 构建 + 运行验证
- [ ] 汇报剩余偏差与后续建议
```

## 第 1 步：锁定范围

开始实现前，先确认这些信息：

- 设计源是 `MasterGo` 还是 `Figma`
- 要还原的是哪个页面、哪个节点或画板
- 目标尺寸，例如 `480x480`
- 当前阶段只做静态视觉，还是要带基础交互
- 是否允许新增或替换本地素材与字体
- 是否有特殊视觉约束，例如“外层不要圆角，内部卡片保留圆角”

## 第 2 步：读取设计数据

- `MasterGo`：先读 `mastergo-reference.md`
- `Figma`：先读 `figma-reference.md`

输出实现前，必须先给用户一个精炼摘要：

- 页面层级结构
- 关键尺寸和坐标
- 颜色与字体
- 需要本地化的素材清单
- 明显无法直接用 `LVGL` 原生表达的部分
- 必须严格对齐的关键设计值清单

## 第 3 步：整理关键设计值

实现前必须先整理“关键设计值对照表”，最少覆盖：

- 页面关键区域
- 卡片
- 图标
- 文本组
- 特殊视觉元素

约束：

- 表中的值必须来自设计数据，不允许凭经验补数字
- 设计值缺失时，要明确标记“设计未提供”，不要自行脑补
- 开始实现后，如果某个值被调整，必须先回到表里更新，并说明原因
- 最终汇报时，应基于这张表说明哪些项已完全对齐，哪些项仍有偏差

## 第 4 步：决定实现策略

默认按这个顺序做决策：

1. 能用 `LVGL` 原生对象和样式表达的，优先原生实现
2. 图标、插图、复杂背景等素材，落地为本地图片
3. 复杂排版、渐变、发光、精细字形效果，如果纯 `LVGL` 很难 1:1，可用局部预合成资源
4. 除非用户明确允许，否则不要把整页做成一张大图
5. 在开始写页面代码前，先明确生命周期方案：页面根对象如何销毁、重复进入时如何避免重复创建、动态字体是否常驻或释放

## 第 5 步：本地资源与字体

资源和字体要集中管理：

- 建议页面模块类似 `xxx_page.c/.h`
- 建议资源模块类似 `xxx_assets.c/.h`
- 路径、颜色 token、字体 getter 尽量集中声明
- 字体优先用设计稿同款；拿不到时必须明确替代方案和偏差
- 如果字体通过 `lv_tiny_ttf_create_file()` 或类似动态接口创建，必须在模块中写清楚“全局常驻”还是“页面退出释放”，不要留成隐式行为

如果需要处理或预合成图片，优先使用固定脚本，而不是每次临时写一段 Python：

```bash
python .cursor/skills/design-to-lvgl/scripts/asset_tool.py inspect "input.png"
python .cursor/skills/design-to-lvgl/scripts/asset_tool.py convert --input "src.png" --output "dst.jpg" --width 480 --height 480 --fit cover
python .cursor/skills/design-to-lvgl/scripts/asset_tool.py compose --spec "spec.json" --output "composed.png"
```

补充说明：

- 如果输入是 `SVG`，先用同一个 `asset_tool.py` 处理，不要临时重写转换脚本
- 当前 `asset_tool.py` 处理 `SVG` 依赖系统里的 ImageMagick `magick` 或 `convert`
- 如果环境里没有这些命令，要先明确报出依赖缺失，再决定改走 `LVGL` 原生绘制或其他方案

## 第 6 步：实现页面

实现时按顺序推进，不要一开始就陷入局部微调：

- 优先保持设计中的层级和视觉关系
- 先搭背景层和大框架，再补局部组件
- 优先让大结构对，再做细节校准
- 关键属性以设计值为准，不凭经验估算
- 固定尺寸页面优先按真实坐标落地，不做二次推导
- 页面上下文要显式管理根对象和关键句柄；如果可能重复创建页面，需同步实现旧对象清理和指针置空

## 第 7 步：验证

至少做以下验证：

1. 构建通过
2. 模拟器可以启动
3. 页面没有明显空白、错位、默认白底遮挡、字体缺失或图片解码失败
4. 与设计稿做人工对比，检查坐标、尺寸、字体、圆角、透明度、对齐是否一致
5. 检查对象与资源生命周期：重复进入页面是否会重复创建根对象、动态字体是否有明确所有权、上下文指针是否存在悬挂引用风险
6. 列出剩余偏差；如果存在偏差，明确写出未对齐项及原因

如果运行中出现内存、图片解码、字体显示问题，优先检查：

- `lv_conf.h` 的内存配置
- 图片格式和真实编码是否一致
- 字体文件是否可读、字形是否覆盖
- 透明度、背景和默认容器样式是否遮挡内容
