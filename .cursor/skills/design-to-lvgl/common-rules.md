# 通用规则

以下规则同时适用于 `MasterGo` 和 `Figma`。先读本文件，再进入来源特化文档。

## 硬约束

1. 这是通用 skill，不要在文档里硬编码固定页面链接、DSL 链接或节点 ID。
2. 调用任意 MCP 工具前，必须先读该工具的 schema 或 descriptor。
3. 设计数据优先级：`真实设计结构 / DSL / 节点信息` > `设计截图` > `主观猜测`。
4. 目标产物必须是 `LVGL` 页面，不要用 `HTML`、`React`、整页截图去替代最终实现。
5. 固定尺寸页面默认按设计稿真实几何值实现，不得擅自改成响应式、自适应或近似布局。
6. 只要 `LVGL` 能表达，`x/y/w/h/radius/color/opacity/font/font-size/font-weight/line-height/letter-spacing/shadow/alignment` 都必须以设计值为准。
7. 未经用户明确同意，不得自行优化、简化、重排、均分、拉伸、补齐留白或修改控件间距。
8. 优先使用 `LVGL` 原生对象、原生布局和原生样式；只有在很难 1:1 表达时，才使用局部预合成图片作为补充。
9. 只要设计中的某个 `UI` 组件能被 `LVGL` 稳定表达，默认应拆成独立对象，不要无故把多个可独立控制的组件合并成一张图或一个不可维护的大块结构。
10. 组件拆分优先级通常是：可交互组件 > 需要单独改样式的组件 > 可能动态更新内容的组件 > 需要复用的局部模块；纯装饰背景、复杂插画、难以 1:1 还原的特效，才考虑保留为局部预合成资源。
11. 如果某个视觉细节无法做到 1:1，必须先明确列出偏差项、原因和替代方案，再继续实现。
12. 所有实际使用到的图片、图标、字体都要落到仓库本地，不要依赖远程临时 URL。
13. 下载或导入的素材必须按页面、模块或资源类型分目录管理；禁止把不同页面的图片、图标、背景统一堆在单一目录下，例如直接混放在 `main/assets` 根目录。
14. 页面和资源命名必须使用稳定、可读的英文小写 `snake_case` 语义名，并与页面主题一致；不要反复生成泛化文件名，例如 `page.c`、`screen.c`、`ui.c`、`assets.c`。
15. 页面代码文件默认使用语义前缀命名，例如 `home_page.c/.h`、`scenes_page.c/.h`、`home_assets.c/.h`；如有状态或子模块，也应保持同一前缀，例如 `home_state.c/.h`。
16. 资源目录名必须与页面或模块语义名一致，例如 `main/assets/home`、`main/assets/scenes`；共享资源再单独放到共享目录，不要用 `images`、`download`、`tmp` 之类无语义目录名承载页面私有素材。
17. 下载得到的素材文件名也要使用语义化命名，不要保留平台默认名或连续编号名，例如 `image.png`、`1.png`、`export-2.png`，除非该文件是原始输入且不会进入最终产物。
18. 不要把页面逻辑全部塞进单一入口文件；页面、资源、字体、辅助函数应拆模块。
19. 页面模块默认必须提供成对的 `create/init` 与 `destroy/deinit` 生命周期接口；如果仓库已有既定页面管理方式，至少要显式复用该模式，不得只写创建不写销毁。
20. 页面可能被重复进入或重建时，创建前必须先处理旧根对象和关联上下文；禁止覆盖旧指针后继续创建新对象。
21. 通过 `lv_tiny_ttf_create_file()` 或等效动态接口创建的字体，必须明确所有权：要么是“全局常驻单例”并写清楚约束，要么提供对应释放路径；不得在重复调用路径中持续累计创建。
22. 每完成一个关键阶段都要验证，至少执行当前仓库的构建与运行 smoke check。

## 固定尺寸页面默认规则

如果设计稿和目标屏幕都是固定尺寸，例如 `480x480`，默认必须遵守：

- 直接按设计稿坐标和尺寸还原，不做自适应推导
- 不为了“代码更优雅”改成 `flex/grid` 等近似布局
- 不为了“视觉差不多”自行微调间距、边距、圆角、字号或对齐
- 不把多个独立元素合并成一个更容易写的容器结构，除非视觉和几何结果完全一致
- 不把复杂局部效果直接删掉；必要时改为局部预合成资源
- 页面级主结构、关键视觉区块和需要精准对齐的模块，默认不用 `flex/grid`；这些区域应直接按设计稿几何值落地
- 只有明显规则化、重复化、后续可能复用的局部子模块，才允许谨慎使用 `flex/grid`，且不能改变最终几何结果

## 实现原则

- 优先保持设计中的层级和视觉关系
- 先搭背景层和大框架，再补局部组件
- 先让大结构正确，再做细节校准
- 优先复用 `LVGL` 原生能力，只有在确实无法稳定表达时才退到局部预合成
- 默认把可独立控制的 `UI` 组件拆成独立对象，便于状态管理、样式复用、交互扩展、局部刷新和后续维护
- 对于天气、时钟、标题、按钮、卡片、图标、标签、列表项这类可单独更新或复用的模块，优先避免整块位图直出
- 如果一个模块已经用预合成图片承载视觉，就不要再重复创建无意义的覆盖容器
- 字体优先用设计稿同款；拿不到时必须明确替代方案和偏差
- 资源和字体应集中管理，避免散落在多个业务文件中
- 页面主模块、资源模块和状态模块应使用统一语义前缀，保证代码文件名与资源目录一眼可对应
- 页面私有素材优先落到对应页面或模块目录，例如 `main/assets/home`、`main/assets/scenes`；跨页面共享素材再单独归到共享目录
- 页面上下文中的根对象、关键子对象和动态字体句柄要有清晰生命周期，销毁后应同步置空，避免悬挂引用
- 默认按嵌入式小内存设备审视对象数量和动态资源，不要因为 PC 模拟可运行就省略释放策略
- 固定尺寸页面优先采用“外层按设计稿固定坐标，内层局部容器相对坐标”的混合策略，不要把整页强行容器化

## 反模式

以下做法默认禁止：

- 只看截图，不读真实设计结构
- 不读 schema 就直接调 MCP 工具
- 用整页大图伪装成“LVGL 页面”
- 把多个本可独立建模的 `UI` 组件合并成单张图或单个难维护的大对象，只为了省事
- 把固定尺寸页面改成“自适应差不多布局”
- 在固定尺寸页面的主结构上滥用 `flex/grid`
- 把不同页面下载来的素材统一丢进 `main/assets` 或其他单一目录
- 反复生成 `page.c`、`ui.c`、`assets.c`、`screen.c` 这类无语义文件名
- 资源目录和页面命名脱节，例如代码叫 `home_page.c`，资源却放在 `main/assets/images` 或 `main/assets/download`
- 因为实现麻烦就擅自改坐标、间距、字号、圆角或对齐
- 用“视觉接近”代替“参数一致”
- 不输出关键设计值对照表就直接开始实现
- 所有代码堆进单个入口文件
- 只改代码不验证
- 发现字体或图片有偏差却不向用户说明
